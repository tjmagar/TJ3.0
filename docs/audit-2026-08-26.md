# TJ 3.0 — Audit and optimization, 2026-08-26

Scope: full read of `src/App.jsx` (3,519 lines), `src/storage.js`, `index.html`,
`vite.config.js`. Severity is keyed to the priority order in `CLAUDE.md`
(1 = never lose written data, 2 = reading and typing quality, and so on).

Verification: `npm test` (16 tests, all passing) and `npm run smoke`
(17 checks in a real Chromium against the production build, all passing).
Both outputs are quoted at the bottom.

## Corrections to the register I wrote before this pass

Two things in `docs/audit-prompt.md` were wrong, and both mattered:

- **1.6 was already half-fixed.** I built that item from the original
  `TJ30-adaptive.jsx` at the repo root. The scaffolding pass had already added
  the API key lookup, `anthropic-version`, and
  `anthropic-dangerous-direct-browser-access` to `askModel`. The AI layer was
  *not* uniformly dead. What remained real: `max_tokens` was hardcoded to 1000
  while callers passed 220–1200, and every failure produced the same opaque

  "almost certainly not valid on the public API." That is no longer true. The
  code was already on `claude-sonnet-5`, which is also valid; I left the choice
  alone and pulled it into a named `MODEL` constant. See "For you to decide".

Everything else in the register held on re-verification against current source.

## Fixed

| # | Severity | Where | Symptom | Cause |
|---|---|---|---|---|
| 1.1 | **P1 — data loss** | `S.get`, `App.jsx:65` | A transient IndexedDB failure destroyed a day's entry | `S.get` caught every error and returned `null`, so "no record" and "store unreadable" were the same answer. A failed read rendered an empty day; the autosave committed it 700ms later. Now a real failure throws and a corrupt record throws; only a genuinely missing key returns `null`. A failed hydration halts the app with an explanation rather than rendering an empty day. |
| 1.2 | **P1 — data loss** | `useSave`, `App.jsx:2171` | Type a sentence, tap to another date within 700ms, sentence gone | The effect returned `clearTimeout`, cancelling the pending write. Now the debounce still coalesces keystrokes, but a key change or unmount **flushes** what is pending instead of dropping it. Same fix applied to the 1400ms index writer. |
| 1.3 | **P1 — data loss** | `App.jsx` shell | iOS freezing the PWA lost anything mid-debounce | Nothing listened for backgrounding. Every debounced writer now registers a flush in a module-level set, and `pagehide` / `visibilitychange` flush them all. Flushing writes already-committed state, so it cannot interrupt a stroke. |
| 1.4 | P2 — visible breakage | `setAm`, `App.jsx:2928` | **"Write it in my voice" produced nothing**; **"Another" did not change the affirmation** | `setAm` spread a closure-captured `am`, so two calls in one handler both built from the same stale object and the second discarded the first. Now routed through the two-segment path in `setD`, which merges against current state. |
| 1.5 | P2 — data loss | `Talk.send`, `App.jsx:1841` | Messages written during an in-flight request were overwritten | `talk` captured at call time, spread again after the `await`. Now functional updates throughout. |
| 1.6 | P2 | `askModel`, `App.jsx:232` | Long generations truncated; every failure read the same | `max_tokens` hardcoded at 1000 regardless of the caller's `maxTokens`. Now honored. A refused key, a rate limit, a server error and being offline now say different things, inline, in the existing `Note` pattern — no modals. |
| 1.7 | P2 — performance | `App.jsx:2281` | Two full IndexedDB key scans per character typed in Journal | Effect depended on `journal`, a fresh object each keystroke. Now depends on the entry count and date. |
| 1.8 | P2 — performance | `Ink`, `App.jsx:2749` | Whole canvas bitmap reallocated on every committed stroke; worse under the eraser, which commits per pointer move | The sizing effect depended on `paint`, whose identity changes with `strokes`. Reassigning `canvas.width` wipes the bitmap. Now sized on real geometry changes only, reaching current paint through a ref. Added a `ResizeObserver` so orientation changes resize correctly without a window resize event. |
| 1.9 | P2 | `App.jsx:2853`, CSS | Full-page notebook mis-sized in standalone | `calc(100vh - 210px)`; `100vh` is not the usable viewport in standalone. The flex column now owns the height, and `.tj-inkfull` uses `100dvh` with a `100vh` fallback. |
| 1.10 | P2 | `importAll`, `App.jsx:2324` | Import reported success even when writes failed; left Talk, week, month and the date lists stale | Now restores everything the app holds, counts failed writes, and says so: `Imported 41, 2 couldn't be written`. |
| 1.11 | P2 — upgrade path | `mergeCore`, `App.jsx:444` | Sections added after a user's `core` was first saved were invisible in the nav forever | Persisted `order` won wholesale over `emptyCore()`. Now reconciled against `SECTIONS`, preserving the owner's ordering and appending anything new. `hidden` is filtered to known, non-fixed ids. |
| 1.12 | P3 | `writeIndex`, `App.jsx:187` | Two rapid saves to the same month shard could interleave and drop rows | Read-modify-write with no serialization. Now chained per shard. A failed read aborts that write rather than persisting a partial shard. |
| — | P3 | `Judgment` | Dead code | `salesRows` was computed on every render and never used. Removed. |
| — | P3 | `index.html` | 404 on every page load | No `favicon` link, so Chrome requested `/favicon.ico`. Now points at the existing icon. |

## Deals removed

Tab, `dealFields`, and the deal `RecordList` are gone. `readJudgment` now reads
only `lib.calls`, and the "Across your reviews" counter counts only calls.

**Stored deal records were deliberately not deleted.** `deals` stays in the
`emptyLib()` shape, so anything already written stays in IndexedDB and still
appears in the JSON export. Removing a tab is not a reason to destroy what was
written into it.

Two copy strings changed because dropping Deals forced them — `"Log a few more
calls or deals first."` → `"Log a few more calls first."`, and the prompt text
`"My deal and call reviews:"` → `"My call reviews:"`. Nothing else in the app's
copy was touched.

## Found, deliberately not fixed

| Finding | Why not |
|---|---|
| **The serif face depends on the network.** `Newsreader` loads from Google Fonts via `@import` inside the CSS string and is not precached by the service worker. Offline, the app silently falls back to Georgia/Iowan Old Style. It degrades rather than breaks, but the typographic identity — which `CLAUDE.md` calls non-negotiable — is network-dependent, and `CLAUDE.md` also says reading and writing work offline. Self-hosting the woff2 files would fix it. | Touches how the design renders and adds asset files. Your call. |
| **The four-month index window.** `readIndex(4)` caps the working set while Talk says "Reads everything you've written here" and every `Mark` reports "from N entries." After four months that claim is quietly false. | Product question, not a bug. Raised below. |
| **Ink: layered canvas, `getCoalescedEvents`, stroke smoothing, `sawPen` palm rejection, pan/zoom.** | Explicitly out of scope for this pass per `CLAUDE.md`, and none can be validated without a physical iPad. Item 1.8 was the one in-scope ink fix. |
| **`npm audit` reports 5 advisories.** All are dev-only (esbuild's dev server) and reach the fix only through `vite@8`, a breaking upgrade. The static production build is unaffected. | Not worth a breaking bump in a defect pass. |

## For you to decide

1. **Calls and Language.** Both are as sales-shaped as Deals was, and `THEMES`
   still carries a `sales` theme feeding the counted layer. You named only
   Deals, so I removed only Deals. Do the others follow?
2. **The "reads everything" claim.** Widen the index window, or change the copy
   so it is true? Provenance honesty is the point of the app, so I would not
   leave it as is.
3. **Model.** Currently `claude-sonnet-5`. `claude-opus-5` is the stronger
   reader for insight quality at roughly 2.5× the input cost. One constant,
   `MODEL` in `App.jsx`.
4. **Self-hosting Newsreader**, per the offline finding above.

### Not verified

  pressure, standalone safe areas, orientation, and the full-page notebook fix
  (1.9) were reasoned about and built correctly, but emulation does not test
  any of it. 1.9 in particular changes standalone layout and needs a real
  device before you rely on it.

  error copy are verified by reading, not by round trip. The no-key degradation
  path *is* covered by the smoke run.

  travel through the same `tj:ink:*` keys and the same code path, but no stroke
  data existed in the run, so that specific claim in `CLAUDE.md`'s checklist is
  reasoned, not executed.
